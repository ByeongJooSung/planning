## 1. 추진 전략
1. **데이터 모델을 먼저 만든다.** 모든 산출물이 하나의 기획 데이터 모델에서 나오므로, 모델·추적성·버전 관리를 가장 먼저 만든다. 변경 요청(CR) 반영과 As-Is/To-Be 비교가 이 기반 위에서만 가능하다.
2. **단계 순서대로, 끝까지 이어지게 만든다.** S1 → S5를 순서대로 만들되, 각 Phase가 끝날 때마다 샘플 프로젝트 2건(신규 1건, 기존 서비스 개선 1건)으로 끝까지 확인한다.
3. **MVP는 파일 기반 + 대화형 워크플로로 검증한다.** 프로젝트 폴더와 JSON 모델, 렌더러를 먼저 만들고, 웹 UI는 검증된 엔진 위에 얹는다(PRD 오픈 이슈 1 결정에 따라 조정).
4. **공공기관 양식과 요구사항 충족 검증은 처음부터 P0으로 다룬다.** 나중에 붙이기 가장 어려운 부분이다.
5. **시스템 구분과 Task는 데이터 모델의 기본 축으로 넣는다.** IA·플로우·스토리보드·프로토타입·RTM이 모두 시스템 구분으로 나뉘므로, 나중에 추가하면 전 단계를 다시 고쳐야 한다.

## 3. Phase별 상세 작업

### P0. 기반 구축 (1~2주)
| No | 작업 | 산출물 |
|---|---|---|
| 0-1 | PRD 오픈 이슈 결정(제품 형태, 공공 양식 기준, Figma 연동 방식, 화면 ID 규칙) | 결정 기록 |
| 0-2 | 기획 데이터 모델 스키마 정의(Project, **System, Requirement, Task**, IANode, Flow, Screen, Component, ChangeRequest, Version) | JSON Schema |
| 0-3 | 프로젝트 폴더 구조, 생성·조회 기능, 시스템 구분 등록(프리셋: 공공 민원형, 일반 서비스형) | 프로젝트 생성 기능 |
| 0-4 | 버전 스냅샷과 모델 Diff 엔진(노드 단위 추가/변경/삭제) | Diff 모듈 |
| 0-5 | 추적성 링크(REQ → Task → 산출물)와 RTM 계산 모듈, 충족 상태 자동 계산, RTM 버전 스냅샷 | RTM 모듈 |
| 0-6 | 샘플 프로젝트 2건 준비(신규 1, 기존 개선 1)와 기대 산출물 정의. 신규 샘플은 **공공 민원형 3개 시스템(대국민·민원포털·심사자)** 과 정보공개 요구사항 포함 | 테스트 픽스처 |

**완료 기준**: 샘플 프로젝트를 만들고 시스템 구분을 등록하고, 모델을 저장·버전 비교·RTM 계산할 수 있다.

| No | 작업 | 산출물 |
|---|---|---|

| 1-2A | 시스템별 Task 자동 분해, Task 편집(선후행·자료 상태), 누락 시스템 점검, 공통 상태값 정의 | Task 분해 기능 |
| 1-2B | RTM 보기 3종(요구사항별, 요구사항 × 시스템 매트릭스, 역추적), 누락·과잉 검사, XLSX·PDF 내보내기(시스템별 시트 옵션) | 요구사항 추적표 |

| 1-4 | 충분성 게이트(필수 항목, 가정으로 진행, 오픈 이슈 등록) | 게이트 |
| 1-5 | 기획안 생성(NEW / EXISTING 목차 분기), 기능 정의표(시스템 구분별), 정책 정의표(시스템 간 공통 상태값) | 기획안 생성기 |
| 1-6 | 기획안 내보내기(DOCX, PPTX, PDF, MD) | 내보내기 |
| 1-7 | 자료 요청서 초안 생성 | 요청서 템플릿 |

**완료 기준**: 게이트 미충족 시 생성이 막히고, 충족 시 모든 REQ가 기획안 섹션에 매핑된 기획안이 나온다. 정보공개 요구사항이 민원포털·심사자·대국민 Task로 분해되고, RTM 매트릭스와 XLSX로 확인된다.

## 4. 검증 계획
| 구분 | 방법 | 기준 |
|---|---|---|
| 요구사항 충족 | RTM 자동 검사 + 샘플별 기대 산출물 비교 | 미매핑 REQ·Task 0건 |
| Task 분해 | 샘플 요구사항의 정답 Task 세트(시스템·행위자·선후행)와 비교 | 필수 Task 누락 0건 |
| 스토리보드 품질 | 검증기(옵션·유효성·메시지 누락) + 기획자 리뷰 체크리스트 | 누락 0건, 개발자 관점 문구 0건 |
| 문서 레이아웃 | PPTX 렌더링 후 넘침·잘림 자동 검사(이미지 비교) | 0건 |
| 내보내기 호환성 | PowerPoint, Keynote, Google Slides, Figma에서 열기 | 깨짐 0건 |
| 변경 관리 | 샘플 CR 영향도 정답 세트와 비교 | 식별률 90% 이상 |

## 5. 리스크와 대응
| 리스크 | 영향 | 대응 |
|---|---|---|
| LLM 생성 결과가 요구사항을 빠뜨리거나 근거 없이 추정 | 요구사항 미충족 | 구조화 출력 + RTM 강제 검사 + 가정 표시, 게이트 통과 전 생성 금지 |
| 공공기관 양식이 기관마다 다름 | 재편집 증가 | PPTX 마스터 업로드와 영역 매핑 기능, 양식별 템플릿 추가 구조 |
| 로그인·보안 때문에 웹 전수조사 불가 | 분석 불완전 | 소스 전수조사 또는 수동 입력으로 대체, 분석 신뢰도 표시 |
| 소스 스택이 다양함 | 파서 부족 | 주요 스택 우선, 미지원 스택은 경로 목록 파일 업로드로 대체 |
| Figma 쓰기 API 제약 | 내보내기 품질 저하 | Figma 플러그인/MCP로 생성, 실패 시 SVG 가져오기 안내 |
| 자동 페이지 분할이 어색하게 잘림 | 가독성 저하 | 디스크립션 항목 단위로만 자르기(항목 중간 분할 금지), 수동 분할 지점 지정 기능 |
| 변경 반영 중 수동 편집 내용 유실 | 작업 손실 | 수동 편집 영역 보존, 반영 전 스냅샷, 충돌 시 선택지 제시 |
| Task 자동 분해가 시스템을 잘못 나누거나 빠뜨림 | 요구사항 누락 | 누락 시스템 점검 규칙(승인 후 공개처 없음, 반려 후 재신청 없음 등) + 작업자 확인 필수 |
