# ADR-002 참조자료 지식베이스 · Task 자동 생성 · 디자인 시스템 · 뷰어 구조

## 1. 참조자료 = 프로젝트 지식
- 올린 파일은 `sources/{SRC-ID}_{파일명}`에 원본 그대로 보관하고, 추출 텍스트는 `knowledge/chunks.json`에 조각으로 색인한다. 조각은 모델(`model/`)과 분리해 스냅샷·Diff 대상에서 뺀다(원본 파일이 기준).
- 조각에는 위치(페이지 `p.3`, 마크다운 제목, `문단 4`, `메일 정보`)를 붙인다. 요구사항 출처와 LLM 근거 인용이 이 위치를 쓴다.
- 검색 1차는 **어절 + 음절 2-gram BM25**. 형태소 분석기 없이 한국어 조사·어미 변화에 어느 정도 강하고, 뷰어(브라우저)에서도 같은 규칙으로 검색할 수 있다. P1에서 임베딩 검색을 더해 혼합한다.
- 지원 형식: txt, md, csv, json, html, eml, docx(mammoth), pdf(unpdf). hwp·pptx·xlsx·이미지는 보관만 하고 `UNSUPPORTED`로 표시한다.

## 2. Task 자동 생성 — 규칙 먼저, LLM은 P1
- 요구사항 등록 시 `--auto-tasks` 또는 `task auto`로 Task를 만든다. 업무 동사(신청·심사·승인·공개·알림·연계·조회·관리)를 시스템 성격(신청 서비스 / 업무·관리자 / 대국민 포털 / 화면 없는 연계)에 대응시키고 처리 순서(선행 Task)를 붙인다.
- 심사가 있으면 “신청인 결과 확인·보완 재신청” Task를 함께 만든다(누락 점검 규칙 F-SYS-04).
- 생성된 Task는 `origin: AUTO`와 근거(`suggestReason`)를 남긴다. 작업자가 수정·삭제할 수 있다.
- LLM 제안(P1)은 같은 출력 형식을 쓰고, 규칙은 LLM 결과의 누락 점검용으로 남긴다.

## 3. 디자인 시스템 — 시스템 영역별, 컨셉 3종에서 선택
- 시스템 성격을 `portal`(국민·비회원) / `service`(민원인·회원) / `admin`(관리자·심사자, ADMIN_WEB) 으로 판정하고, 성격마다 방향이 다른 컨셉 3종을 제안한다. 컨셉 = 토큰(색·글꼴·모서리·컨트롤 높이·간격·그리드·그림자) + 레이아웃 규칙(GNB, 로고, 검색 영역, 목록, 페이지네이션, 버튼, 밀도, 푸터).
- 대국민 포털 컨셉 A는 범정부 UI/UX 가이드라인(KRDS)의 **구성 원칙**(상단 메가메뉴, 왼쪽 로고, 표 목록, 번호 페이지네이션, 전체 푸터)을 따른다. KRDS의 실제 색상·컴포넌트 값을 그대로 쓴 것은 아니며, 기관 CI 반영은 토큰 조정(F-DS-06)으로 한다.
- 컴포넌트 ID는 모든 컨셉에서 같고 컨셉은 모양만 바꾼다. 그래서 컨셉을 바꿔도 스토리보드는 그대로 다시 그려진다.
- 스토리보드 컴포넌트는 `ui.component`로 디자인 시스템 컴포넌트를 참조한다. 컨셉 선택 전 사용, 없는 컴포넌트 사용은 저장 시 오류다. 새 컴포넌트는 `design component-add`로 먼저 추가한다(`origin: ADDED`, `addedFor`).

## 4. 뷰어 — 정적 HTML, 편집은 CLI
- `planning view`는 모델·RTM·Diff·지식 조각을 넣은 HTML 한 파일을 만든다. 서버 없이 열리고, 참조자료 검색·프로토타입 조작도 브라우저 안에서 동작한다.
- 화면 구성: 프로젝트 목록 → 프로젝트 상세(LNB가 프로젝트 메뉴로 바뀜) → Task 상세(플로우·화면설계서·프로토타입) / 통합 산출물.
- 와이어프레임·프로토타입은 같은 렌더러(`wire.js`)가 디자인 시스템 토큰을 CSS 변수로 받아 그린다.
- 파일 올리기·편집은 CLI로 한다. 웹에서 올리고 편집하는 서버 모드는 P7에서 같은 코어 위에 만든다.
