## 1. 실행 형태 — `planning serve` 한 프로세스
- Node HTTP 서버 하나가 API와 화면(뷰어의 편집 모드)을 함께 낸다. 프로젝트 데이터는 지금과 같은 파일 저장소(`<root>/<코드>/`)를 쓰고, CLI로 만든 프로젝트도 그대로 열린다.
- 계정·세션·멤버·초대·AI 설정은 `<root>/.service/service.json`에 둔다(작은 팀 규모). 쓰기는 임시 파일 → 이름 바꾸기로 원자적으로 하고, 프로젝트 쓰기는 프로젝트마다 한 줄로 세운다.
- 편집은 서버가 서비스 코어(`src/service/core.ts`의 `execute`)를 실행해 무결성 검사 후 저장한다. 화면은 저장 결과(RTM·Diff·프롬프트까지 계산된 데이터)를 받아 다시 그린다.
- 배포: `Dockerfile`(데이터 볼륨 `/data`, 비어 있으면 샘플 프로젝트 복사), `render.yaml`(Render 블루프린트, 영구 디스크), `vercel.json`(Vercel 함수). 사내 서버에서는 `node dist/cli.js serve`.

### 1-1. 저장소 두 가지 — 파일과 Redis
서버리스(Vercel)는 디스크가 남지 않고 요청이 여러 인스턴스로 나뉜다. 그래서 저장을 두 층으로 나눴다.
| 층 | 한 프로세스 (`planning serve`) | 서버리스 (Vercel) |
|---|---|---|
| 계정·세션·멤버·초대·AI 설정·생성 결과·댓글 (`Kv`) | `FileKv` — `.service/kv.json` | `UpstashKv` — Upstash Redis REST |
| 프로젝트 모델·조각·스냅샷·원본 파일 (`ProjectRepo`) | `FsRepo` — CLI와 같은 폴더 구조 | `KvRepo` — 같은 Redis (`prj:{코드}:…`) |
- 계정 저장소는 메모리에 캐시하지 않고 요청마다 읽는다(인스턴스 사이 일관성). 가입 이메일 중복·첫 가입자·프로젝트 코드 중복은 `SET NX`로 원자적으로 막는다.
- 프로젝트 쓰기는 `SET NX EX` 잠금으로 한 줄로 세우고, 저장소는 이전·새 상태의 차이(모델, 바뀐 조각, 새 스냅샷, 원본 파일 추가·삭제)만 쓴다.
- Vercel 첫 요청 때 저장소가 비어 있으면 샘플 프로젝트를 넣는다(`SEED_EXAMPLES=0`이면 안 함). `PLANNING_SECRET`이나 Redis 연결이 없으면 설정 안내 화면을 낸다.

## 2. 권한 — 만든 사람이 운영자
| 권한 | 할 수 있는 일 |
|---|---|
| OWNER 운영자 | 프로젝트를 만든 사람. 멤버 초대·권한 변경·내보내기, 프로젝트 AI 설정, 이름 변경·삭제. 운영자는 여럿 둘 수 있고 마지막 운영자는 권한을 낮추거나 나갈 수 없다 |
| EDITOR 작업자 | 요구사항·Task·참조자료·디자인 시스템·산출물 편집, AI 생성·적용, 스냅샷 |
| VIEWER 열람자 | 보기, 디자인 이미지 댓글 |

- 초대: 운영자가 이메일·권한으로 초대하면 14일짜리 링크가 한 번 보인다(서버에는 토큰 해시만 저장). 초대받은 이메일로 가입·로그인하면 첫 화면에 초대가 뜨고, 링크로 들어와도 된다. **초대받은 이메일 계정만** 수락할 수 있다.
- 서버에 운영자가 없는 기존 프로젝트(CLI로 만든 것)는 첫 가입자에게 맡긴다.
- `PLANNING_SIGNUP=closed`면 초대받은 이메일만 가입한다(첫 가입자 예외).

## 3. 인증
- 비밀번호 scrypt(솔트 16바이트) 해시. 세션은 무작위 32바이트 토큰을 HttpOnly·SameSite=Lax 쿠키로 주고 서버에는 SHA-256 해시만 둔다(30일).
- 쓰기 요청은 `X-Planning: 1` 헤더가 있어야 받는다 — 다른 사이트의 폼·요청을 막는다(CSRF). HTTPS 뒤에서는 `COOKIE_SECURE=1`로 Secure 쿠키.
- 같은 주소·이메일로 15분에 10번 넘게 로그인에 실패하면 막는다.

## 4. AI 호출 설정 — 프로젝트별 · 개인별
- 호출 방법 두 가지:
  - `anthropic`: Claude API(`@anthropic-ai/sdk`, 기본 모델 `claude-opus-5`, adaptive thinking, 스트리밍으로 받아 `finalMessage()`).
  - `openai-compatible`: `/chat/completions`를 여는 로컬 LLM(Ollama·LM Studio·vLLM) 또는 외부 호환 API. 주소·모델·키(선택)를 넣는다.
- 설정 위치와 우선순위: (멤버가 “내 개인 설정 사용”을 켠 프로젝트) 개인 → **프로젝트 설정(운영자가 등록, 멤버 공통 기본값)** → 개인 → 서버 기본(`ANTHROPIC_API_KEY`).
- 키는 AES-256-GCM으로 암호화해 저장한다. 암호화 키는 `PLANNING_SECRET`(없으면 `.service/secret.key`, 0600). **API 응답에는 키가 절대 들어가지 않고**(“저장됨” 여부만), 프로젝트 설정의 주소도 운영자에게만 보인다. 멤버는 호출 방법과 모델 이름만 본다. 키를 비우고 저장하면 기존 키를 유지한다.
- AI 생성은 작업자 이상만 부를 수 있다(비용). 결과 JSON은 코드 블록·설명·`<think>` 블록이 섞여도 첫 JSON을 꺼내 읽고, 형식이 틀리면 화면의 검사 결과로 보여 준다.

## 5. 생성 결과 · 댓글
- AI 생성 버전과 디자인 댓글은 프로젝트별 KV(`.service/kv/<코드>.json`)에 둔다. 서비스 모드에서는 “적용”이 곧 모델 저장이다(정적 뷰어의 덧씌우기 방식은 쓰지 않는다).
- 디자인 미세조정은 적용 전 디자인 시스템을 이력에 남겨 `design.revert`로 되돌린다(개정 번호는 계속 오른다).

## 6. 하지 않은 것 (다음 단계)
- 메일 발송(초대 링크는 직접 전달), 비밀번호 재설정 메일, SSO. 동시 편집 충돌 알림(마지막 저장 우선). 여러 서버 인스턴스(파일 저장소라 한 인스턴스).
